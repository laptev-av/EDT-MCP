# Изменить формат хранения эталонной конфигурации в репозитории

## Проблема

Сейчас эталонная тестовая конфигурация хранится как полноценный EDT-проект в каталоге `TestConfiguration/` (структура `src/`, `DT-INF/PROJECT.PMF` и т.д.).

Такой формат неудобен для повторного использования:

- нельзя просто «импортировать конфигурацию» в уже существующий или новый workspace — нужно копировать/открывать готовый EDT-проект целиком;
- рабочий EDT-проект оказывается жёстко привязан к layout репозитория;
- усложняется автоматизация CI: headless-импорт и воспроизводимое развёртывание тестового стенда требуют отдельных шагов.

## Предложение

Хранить эталонную конфигурацию **не как EDT-проект**, а как **выгрузку в XML** в каталоге:

```
fixtures/edt_xml/
```

Рабочий EDT-проект при этом **не хранится в репозитории** и создаётся локально (или в CI) импортом из `fixtures/edt_xml`.

### Способы импорта

1. **EDT GUI**: *Import → Configuration from XML Files* — указать путь `fixtures/edt_xml`, задать имя проекта (например, `TestConfiguration`).
2. **MCP / CLI**: инструмент `import_configuration_from_xml` (обёртка над `IImportConfigurationFilesApi.importProject`) — импорт из абсолютного или относительного пути к `fixtures/edt_xml`.

## Ожидаемый результат

- В репозитории — только переносимый XML-источник конфигурации, без EDT-метаданных проекта.
- Локально и в CI один и тот же сценарий: создать workspace → импорт из `fixtures/edt_xml` → запустить E2E проекта `TestConfiguration`.
- Упрощается интеграция с headless EDT и MCP-инструментами импорта/экспорта.

## Связанные компоненты

- `import_configuration_from_xml` — уже реализован в MCP-сервере
- `tests/e2e/run_e2e_tests.py` — параметр `--project TestConfiguration`
- `.github/workflows/e2e-tests.yml` — input `project_name`
